# jdan t9

把一段文字翻成**九宫格键盘（T9）上实际要按的数字键**。汉字先转拼音再映射（中 → zhong → 94664），英文字母直接映射（hi → 44）。

## 原理

九宫格键位是固定的:

```
2 abc   3 def   4 ghi   5 jkl
6 mno   7 pqrs  8 tuv   9 wxyz
```

映射本身就 8 组、一张表。真正的重头是**汉字 → 拼音**这一步:它不是算出来的,是纯查表(「中」和它的 Unicode 码位之间没有规律,只能靠一份读音字典)。所以这条链是:

```
汉字  ──(拼音字典)──▶  拼音字母  ──(T9 键位表)──▶  数字键
中                     zhong                    94664
```

拼音字典用 [`go-pinyin`](https://github.com/mozillazg/go-pinyin)(内嵌 Unicode Unihan 校对来的 ~4 万条读音,离线可用,处理多音字)。「T9 键位表 + 渲染」这层是纯逻辑、0 依赖(`internal/t9x`)。

> 为什么中文这步离不开数据字典:`jdan` 是编译好的离线二进制,里面没有「智能」——它想知道「中=zhong」,这条信息就必须事先存在字典里。这跟 `jdan alpha` 的 `a=1`(能用公式算)本质不同,拼音只能查。

## 用法

```bash
jdan t9 中文              # 逐字对照 + 底部整串数字
jdan t9 "你好 hi 2024"    # 中英数字混排
echo 中国 | jdan t9       # 管道
jdan t9 中文 --digits     # 只出数字串（可管道）
jdan t9 中文 --json       # 机读
```

输出示例:

```
$ jdan t9 "你好 hi 2024"
你    ni   64
好    hao  426
hi    —    44
2024  —    2024
─────
64 426 44 2024
```

- 每个**汉字**一行:字 + 拼音 + 数字键。
- 每段**英文单词**一行(拼音列显 `—`)。
- **阿拉伯数字**原样透传(它们本身就是键)。
- **空格 / 标点**静默跳过;其它无法映射的字符(emoji、别的文种)跳过并计数(走 stderr,保持 stdout 干净可管道)。

### Flags

| flag | 默认 | 说明 |
|------|------|------|
| `--digits` | false | 只输出整串数字(省掉逐字对照) |
| `--json` | false | 结构化输出(`units[]` + `skipped`) |

无参数时从 stdin 读。

## 局限

- **多音字取最常见读音**(go-pinyin 默认),个别可能不准。比如「行」默认 xíng(`9464`),但「银行」的「行」读 háng(`4264`)——本工具逐字取常见音,不做词组消歧。
- 只做「每字全拼的确定性按键序列」,不是真实输入法(没有候选、词频、整句联想)。

## 实现

```
internal/t9x/t9x.go   LetterDigit / LettersToDigits / Result 渲染   纯逻辑，0 依赖
internal/cli/t9.go    切词（汉字/英文/数字）+ 边缘调 go-pinyin       IO
```

- **纯函数好测**:`LettersToDigits("zhong")=="94664"` 直接断言;`Result.Render`/`FormatJSON` 用手搓单元测。
- **依赖隔离**:`t9x` 不 import go-pinyin,汉字→拼音的注入点 `pinyinOf func(rune) string` 在 CLI;测试灌假字典跑纯逻辑,另有一条用真实 go-pinyin 的集成测试兜底(`中文 → 94664 936`)。

## 有意不做

| 不做 | 原因 |
|------|------|
| 反向(数字 → 中文) | 那是输入法候选,一串数字对应海量汉字,歧义爆炸 |
| 词组消歧 / 多音字 100% 准 | 逐字取常见读音,标注局限;做整句消歧是另一个量级的工程 |
| 自造拼音表 | 无本地权威数据源,手编几万条会出错;复用 go-pinyin 的校对字典更靠谱 |

跟 `jdan morse`(摩斯)、`jdan alpha`(字母序号)同属「文字 ↔ 编码」一类。
