# Unix 毫秒时间戳可读化命令

## Problem Frame

在日常排障和日志分析中，开发者经常拿到 Unix 时间戳（毫秒）数值，但需要反复切换工具或写临时代码才能快速看懂时间。
为 `jdan` 增加一个轻量命令可减少这类摩擦，让时间戳在命令行中即时可读。

## Requirements

**命令入口**
- R1. 新增子命令 `jdan unix-time`，用于将 Unix 时间戳转换为可读时间。
- R2. 命令支持两种输入方式：命令参数优先（如 `jdan unix-time 1711843200000`），若无参数则从 `stdin` 读取单个值。

**输入与解析**
- R3. 输入接受纯数字字符串；非数字输入返回明确错误并以非零退出码退出。
- R4. 命令采用智能识别规则：10 位按秒级时间戳解析，13 位按毫秒级时间戳解析。
- R5. 对超出可解析范围或格式不合法的输入，返回可读错误提示（不 panic）。

**输出行为**
- R6. 默认按本机本地时区输出。
- R7. 输出格式为简洁单行时间字符串（无额外标签），例如 `2026-03-31 10:20:30 +08:00`。
- R8. 成功转换时仅输出转换结果，不附带调试信息。

## Success Criteria
- 输入一个 10 位或 13 位有效 Unix 时间戳时，命令在一次调用内输出正确的本地时区可读时间。
- 输入非法值时，用户能看到明确错误原因并获得非零退出码。
- 通过参数输入和 stdin 输入两种路径都能稳定工作。

## Scope Boundaries
- 不支持批量多值转换（一次仅处理一个值）。
- 不提供反向转换（可读时间转时间戳）。
- 不在此阶段支持自定义输出模板或语言本地化。

## Key Decisions
- **采用 `unix-time` 作为命令名**：语义直观，与输入数据类型直接对应。
- **默认本地时区输出**：符合日常开发排障的直觉阅读习惯。
- **采用 10/13 位智能识别**：减少参数心智负担，兼容常见秒/毫秒两种来源。
- **支持参数 + stdin 单值输入**：既保留直接调用体验，也兼容管道场景。

## Dependencies / Assumptions
- 依赖 Go 标准库 `time` 完成解析与格式化。
- 本机时区由系统环境决定（如 `TZ` 或操作系统时区设置）。
