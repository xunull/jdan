# jdan wifi — WiFi 状态与信道拥挤分析

看当前无线连接，并分析周边 AP 的信道占用，给出换信道建议。

回答的是**菜单栏不会告诉你的事**：信道撞没撞、SNR 够不够、协商到了哪代协议、邻居把哪个频段占满了。

## 关于 SSID：拿不到，而且不需要

macOS 14 起把 **SSID 和 BSSID 归类为位置信息**（WiFi 指纹能定位到街区级）。没有定位服务权限的进程拿到的是 `<redacted>`。

CLI 二进制**没法自己申请这个权限** —— TCC 授权绑定 app bundle，`jdan` 继承的是终端的权限。要看到 SSID：

> 系统设置 → 隐私与安全性 → 定位服务 → 勾选你的终端 App

但这个命令的核心价值一点都不依赖 SSID。信道、带宽、信号、噪声、协议、加密方式、以及周边全部 AP 的射频数据**都不受限制** —— 而信道拥挤分析要的正是这些。SSID 只是个标签，你自己连的哪个网菜单栏就写着。

### 关于绕过

`scutil show State:/Network/Interface/en0/AirPort` 的 `CachedScanRecord` 里有明文 SSID 和 BSSID（macOS 只脱敏了便利字段，没管原始 beacon 缓存）。

**`jdan` 不用这条路。** 它是绕过隐私控制的未公开侧信道，Apple 随时会堵且不会有 changelog，blob 格式内部无版本，失败模式是「静默给出错误 SSID」而非报错。`jdan` 的 `secrets-scan` / `pwned` 都在帮用户守隐私，转头自己绕 TCC 不合适。

## 为什么不是 `airport`

网上几乎所有 macOS WiFi 脚本教程都在教用 `airport`。实测 macOS 26.5.2：

| 路径 | 结果 |
|---|---|
| `airport` | **文件已删除**。不是废弃警告，是二进制不存在了 |
| `networksetup -getairportnetwork en0` | **谎报**「You are not associated with an AirPort network」—— 而实际连着 |
| `wdutil info` | 需要 `sudo` |
| `system_profiler -xml SPAirPortDataType` | 免 sudo、数据完整，代价是单次约 1.7 秒 |

`networksetup` 那条最坑：它不报错，而是**告诉你没连网**。任何按「先判断是否连接」写的代码都会走进错误分支。

`jdan wifi` 用 `system_profiler`。

## 信道分析：两个量，不是一个分

输出里是**同信道 BSS 数**和**邻道噪声**两个值，不是一个合成的「干扰分」。这是刻意的 —— 它们是两种不同的物理机制：

**同信道（完全重叠）走空口时间。** CSMA/CA 下，任何 RSSI 高于载波侦听门限（20MHz OFDM 约 **-82 dBm**）的 AP 都会让你**退避**。代价是被占走的空口时间，**跟它比你强多少基本无关** —— 强 10dB 和强 30dB 都是让你 defer，不是让你多 defer。

**邻信道（部分重叠）走线性功率求和。** 不可解码的能量当作噪声，这里功率才是真的线性相加（mW 相加后转回 dBm）。

压成一个分会让强信号邻居主导排序，**低估「很多个中等强度同信道 BSS」这种真实很糟的情况**。商业产品常用的「加权功率求和」就有这个问题。

排序按同信道 BSS 数优先，并列时看邻道噪声。

### 重叠怎么算

**2.4GHz**：信道间隔只有 5MHz，而 20MHz 标称带宽的实际占用更宽（DSSS 约 22MHz，OFDM 频谱模板在 ±11MHz 处才降到 -20dBr）。所以：

```
重叠 ⟺ |n - m| ≤ 4，重叠度 = (5 - |n-m|) / 5
```

这就是 1/6/11 相隔 5 的由来。

注意 **1/5/9/13 是折中方案不是干净方案** —— 相隔 4，按上面的规则是弱重叠（0.2）。它用轻微邻道干扰换一个额外可用信道，在 AP 密集环境下可能划算，但不是「互不重叠」。

**5GHz/6GHz**：40/80/160MHz 信道在**固定栅格**上，不能任意起始：

```
80MHz  合法块: {36,40,44,48} {52,56,60,64} {100,104,108,112}
               {116,120,124,128} {132,136,140,144} {149,153,157,161}
160MHz 合法块: {36…64}  {100…128}      ← 全世界只有这两个
```

macOS 报的是 **primary channel 不是块起始**。所以 `44 @ 80MHz` 实际占用 `{36,40,44,48}`，不是 `{44,48,52,56}`。按「往后数 4 个」实现会得到后者 —— 形状正常，完全错误，还会把 `161@80` 算成 `{161,165,169,173}`（169/173 在 5GHz 根本不是合法信道号）。

跨宽度重叠度 = 子信道集合交集 ÷ **本机**集合大小。本机 `36@80`（占 4 个）遇上邻居 `44@20` 是 0.25，遇上 `44@160` 是 1.0。

## 扫描结果不稳定，所以要多次采样

实测同一时刻连跑 6 次：

```
13 / 14 / 17 / 15 / 17 / 17 个邻居      ← 31% 波动
```

这不是时段差异，是扫描本身。所以 `--samples` 默认 3 次取并集，页脚会告诉你有几个 AP 是「间歇可见」的。

**「0 个 AP」不等于「信道空」。** 只有在 N 次采样**全部**为 0 时才标记为真空，否则可能只是这次没扫到。推荐一个零样本信道时输出会提醒你这一点。

## 常用法

```bash
jdan wifi                    # 当前状态 + 全频段信道分析
jdan wifi --band 5           # 只看 5GHz
jdan wifi --samples 5        # 多采样几次（更准，更慢）
jdan wifi --all-channels     # 列出全部候选信道而非前 8 个
jdan wifi --json | jq        # 完整数据
```

| 选项 | 默认 | 说明 |
|---|---|---|
| `--samples N` | 3 | 采样次数。扫描不稳，多次取并集 |
| `--band` | 全部 | 只分析指定频段：`2.4` / `5` / `6` |
| `--interface` | 自动 | 指定无线接口（默认选已连接的那个） |
| `--all-channels` | 关 | 列出全部候选信道 |
| `--no-color` | 关 | 关闭染色（也尊重 `NO_COLOR`） |
| `--json` | 关 | 完整数据，不受展示层裁剪影响 |

## 换信道的代价

**DFS 信道（52-144）不是免费的。** 切过去后 AP 必须先静默监听 **60 秒**才能发射（ETSI 气象雷达信道 120/124/128 是 **600 秒**），期间不能用；之后遇到雷达还会被强制跳频。推荐落在这个区间时输出会提醒。

**候选信道必须能承载当前带宽。** 本机跑 80MHz 时不会推荐 ch165 —— 那是孤立的 20MHz-only 信道，换过去带宽掉 4 倍，而它「看起来最空」恰恰因为只占一个 20MHz 子信道。

**只在明显更优时才给建议。** 同信道 BSS 数必须严格更少才推荐换。换信道有成本，给个边际收益的建议比不给更糟。

## JSON 输出

```bash
jdan wifi --json | jq '.bands[] | select(.band=="5GHz") | .recommended_channel'
```

几条约定：

- **`ssid_redacted` 是显式布尔**，不用去比 `"<redacted>"` 字符串
- **`adjacent_noise_dbm` 无邻道干扰时是 `null`** 而不是 0 —— 0 dBm 是 1 毫瓦，会被读成极强信号
- `--all-channels` / 展示层裁剪**不影响 JSON**，永远输出全部信道和全部邻居
- 每个邻居带 `seen_in_samples` 和 `intermittent`

## 平台

**目前仅 macOS。**

Linux 上 `/proc/net/wireless` 只有信号强度，没有信道也没有邻居扫描 —— 交付不了这个命令的核心价值。拿完整数据需要 `iw` 或手写 nl80211 netlink，尚未实现。其他平台报清晰错误而非崩溃。

Linux 上没有 SSID 脱敏，这是 macOS 独有的限制。
