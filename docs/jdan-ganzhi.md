# jdan ganzhi

干支**四柱（八字）**：给一个时刻，算出年、月、日、时四个干支，附五行阴阳与年柱纳音。另含六十甲子查询与反查。**0 新依赖**。

## 它能干什么

```bash
$ jdan ganzhi 1990-05-20 14:30
输入: 1990-05-20 14:30（CST）

  年柱  庚午   金火  阳  马年
  月柱  辛巳   金火  阴  （立夏 起）
  日柱  乙酉   木金  阴
  时柱  癸未   水土  阴

  纳音  路旁土        口径  节气年（立春为界）

$ jdan ganzhi                        # 现在
$ jdan ganzhi 1990-05-20             # 不给时刻 → 只出三柱
$ jdan ganzhi --of 甲子
甲子  六十甲子第 1 个
  天干 甲 阳木   地支 子 水   生肖 鼠
  纳音 海中金

$ jdan ganzhi --table                # 六十甲子全表
$ jdan ganzhi 2026-07-27 23:30 --late-zi
$ jdan ganzhi 1990-05-20 14:30 --json
```

## 子命令 / flags

模式分派用 flag，**不做内容嗅探**——三种模式的输出形状完全不同，`--json` 消费方不该先判类型才知道拿到的是什么。与 `jdan lunar` 的 `--to-solar`/`--festivals` 同一套路。

| flag | 作用 |
|---|---|
| `--of <干支>` | 反查序号、五行、纳音。阴阳不配的组合（如「甲丑」）会报错 |
| `--table` | 列六十甲子全表 |
| `--late-zi` | 23:00–23:59 用晚子时派（日柱不翻） |
| `--tz <IANA>` | 声明挂钟属于哪个时区。**会改变答案**，详见下文 |
| `--json` | 结构化输出 |

位置参数是 `[日期] [时刻]`，默认现在。`--table` 与 `--of` 互斥，两者都不接位置参数。

## 两套口径，都对，各自标注

这是本命令最要紧的一件事。

| | 分界 | 谁在用 |
|---|---|---|
| **生肖年** | 正月初一（春节） | 过年说「今年马年」；`jdan lunar` 输出的 `ganzhi` |
| **节气年** | 立春 | 八字的年柱；本命令 |

春节在 1/21–2/20 之间浮动，立春固定在 2/3 前后，所以**每年有一段最长约 30 天两者不一致**。

```
        立春              春节
  ───────┼─────────────────┼────────▶
         │◀─── 差异期 ────▶│
   生肖年 乙巳（蛇）        生肖年 丙午（马）
   节气年 丙午（马）        节气年 丙午（马）
```

**这不是 bug，是历法事实。** 绝大多数在线八字工具默默用一套、绝口不提另一套。jdan 两套都给、都标口径，**差异期内两个命令互相指路**：

```
$ jdan lunar 2026-02-10
公历: 2026-02-10 (周二)
农历: 乙巳年 腊月廿三  (生肖 蛇)
口径: 生肖年（正月初一为界）

提示: 此日节气年（丙午，立春为界）与生肖年（乙巳）不同。
      八字年柱用节气年，请用 jdan ganzhi。
```

非差异期两边都不打这行。

## 推算规则

| 柱 | 怎么定 |
|---|---|
| **年柱** | 以立春为界定节气年 Y，序号 = `(Y−4) mod 60` |
| **月柱** | 月支由 `jieqix.PrevMajor` 定（立春→寅、惊蛰→卯…）；月干走**五虎遁** |
| **日柱** | 儒略日连续推算，相位由权威锚点钉死 |
| **时柱** | 时支每两小时一辰（23:00–00:59 子）；时干走**五鼠遁** |

**月柱由「节」定，不由公历月定。** 12 个「节」分月，12 个「气」不分——搞混会整体错半个月且看起来完全合理。

**五虎遁**（`寅月干 = (年干×2+2) mod 10`）与**五鼠遁**（`子时干 = (日干×2) mod 10`）的正确性由**口诀**验，不是反过来：测试里断言的是「甲己之年丙作首、乙庚之岁戊为头」「甲己还加甲、戊癸壬子是真途」，公式对不对由口诀说了算。

## 日柱的相位有外部依据

日干支是一条从未中断的 60 日循环，只需钉住相位。

**权威锚点两条**（zh.wikipedia「干支」条目）：`1912-02-18` 与 `1949-10-01` 都是**甲子日**。

三重验证：

1. 两日相隔 **13740 天 = 229 × 60**，整除 → 两条陈述自洽
2. `jdan lunar 1912-02-18` → 壬子年 正月初一 ✓ 与维基所述农历日期一致
3. `jdan lunar 1949-10-01` → 己丑年 八月初十 ✓ 同上

第 2、3 条用的是本仓库已有且已验证的 `lunarx`，构成一条独立校验链。

**实现里写的是锚点日期本身，不是推导出来的偏移常数**：

```go
var jiaziAnchorJDN = jieqix.JDN(1912, time.February, 18)  // 这一天是甲子日
out.Day = FromIndex(jieqix.JDN(y, m, d) - jiaziAnchorJDN)
```

两个理由：那个偏移常数是中间结果，直接写会让真正的事实消失在魔数里；而且相减抵消 JDN 的整体平移，万一 JDN 有系统性偏差日柱不受影响。

## 子时分歧

23:00–23:59 算次日还是当日，**两派都有传承，没有权威裁决**。它影响四柱里的**两柱**：

```
2026-07-27 23:30
  默认（23:00 换日）: 日柱 癸卯（7/28 的）  时柱 壬子（7/28 日干推）
  --late-zi        : 日柱 壬寅（7/27 的）  时柱 庚子（7/27 日干推）
```

默认取主流派（与多数万年历一致），落在这一小时内时输出会**标明用的是哪派**。不标的话，用户拿去对别的万年历会发现对不上却不知道为什么。

## 不给时刻就不出时柱

```bash
$ jdan ganzhi 1990-05-20
输入: 1990-05-20（CST，未提供时刻）
...
  时柱  ——   （未提供时刻）
```

默认成 00:00 会凭空造出一个子时，而用户并没有提供那个信息。`--json` 里 `hour` 显式为 `null` 而不是省略字段——省略会让消费方分不清「没给时刻」和「字段名写错了」。也不显示那个内部占位的 `00:00`，显示了会让人以为是自己输的。

## 时区

默认中国民用时：**1929-01-01 起 UTC+8，之前用北京地方平太阳时 UTC+8:05:43**。

`--tz` 声明**挂钟读数属于哪个时区**，会改变答案。改哪几柱取决于你固定的是哪一头：

| 输入形式 | 固定的是 | 变的是 |
|---|---|---|
| 给了日期时刻 | 挂钟读数 | **年柱月柱**（它们跟节气的绝对时刻比） |
| 没给（用现在） | 绝对瞬间 | **日柱时柱**（它们看本地几点） |

实测（2026 立春 = 04:02 CST = 05:02 JST）：

```bash
$ jdan ganzhi 2026-02-04 04:30                    # 年柱 丙午（立春后）
$ jdan ganzhi 2026-02-04 04:30 --tz Asia/Tokyo    # 年柱 乙巳（=CST 03:30，立春前）
                                                  # 两边日柱都是己酉
```

⚠️ 这和 `jdan jieqi` 的 `--tz` 不一样——那个只改显示，答案不变。

## 内部架构 & 可测性

```
internal/ganzhix/
  tables.go     干支/生肖/五行/阴阳/60 项纳音 + Pillar/Sexagenary/IndexOf
  ganzhix.go    四柱推算
依赖方向（无环）:  lunarx ──▶ ganzhix ──▶ jieqix
```

干支表原本在 `lunarx` 里未导出，本次**搬到 ganzhix 并导出**，`lunarx.GanzhiYear/Zodiac` 改为转发。方向选 ganzhix 拥有，是因为 lunarx 有 1900–2100 硬边界而 ganzhix/jieqix 没有——反向依赖会让人误以为 ganzhix 也被限住了。

`fromGanZhi(甲, 丑)` 这类阴阳不配的组合**直接 panic**，不静默兜底：那是调用方的逻辑错误，返回一个「最接近」的柱会让错误一路传下去。60 个合法组合正是 lcm(10,12)，不是 10×12=120。

## 纳音数据

30 组，三个独立来源交叉比对，分歧处取多数：

| # | 干支 | 分歧 | 采用 |
|---|---|---|---|
| 16 | 甲午乙未 | 沙中金 / 砂中金 | 沙中金 |
| 21 | 甲辰乙巳 | 覆灯火 / 佛灯火 | 覆灯火 |
| 24 | 庚戌辛亥 | 钗钏金 / 钗环金 | 钗钏金 |

这三处是民俗文献里真实存在的异体写法，不是抄错。纳音名没有单一权威版本，所以取通行写法并把异体记在 `tables.go` 注释里，而不是假装只有一种。

## 有意不做

- **黄历宜忌 / 神煞 / 大运流年 / 命理解读** — 这是历法工具，不是算命工具
- **真太阳时校正** — 严格的八字要按出生地经度修正（东经每差 15° 差 1 小时，再加均时差），需要额外输入经度，是另一套语义
- **引 lunar-go / sxtwl** — 引库会让仓库里同时存在**两套互不知情的农历实现**，`jdan lunar` 与 `jdan ganzhi` 对同一天给出不同干支而矛盾埋在两份彼此不知道对方存在的代码里。自己实现是让两个口径出自同一份代码、能被同一份文档说清楚的唯一路径

## TL;DR

四柱八字，年柱以立春为界并与 `jdan lunar` 的生肖年互相指路，月柱跟节气走，日柱相位有外部权威锚点且写的是锚点日期不是魔数，子时分歧两派可选且会标明，不给时刻就不编时柱。
