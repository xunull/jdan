# jdan barcode

生成 **Code128 一维条码**（库存 / 物流 / 快递单常用）。**0 新依赖**：内嵌 Code128 模式表
自己编码、自己渲染，不引外部 barcode 库。

## 原理：Code128 怎么把字符变成黑白条

一维条码 = **一排竖条（bar）+ 空白（space），靠宽度编码数据**。Code128 的规则：

```
[静区] Start [数据符号...] 校验符 Stop [静区]
```

- 共 **107 个符号**（值 0–106）。除 Stop 外每个符号宽 **11 模块**（module = 最细条的单位宽），
  由 **3 条 + 3 空 = 6 个元素**组成，每个元素宽 1–4，加起来正好 11。
  例：值 0 → 宽度模式 `212222`（条2 空1 条2 空2 条2 空2）。一张 **107 行固定模式表**就把
  「符号值 → 6 个宽度」定死了。
- **3 套字符集**：A（大写+控制符）、**B（大小写+数字+标点，最通用）**、**C（数字成对，
  一个符号编 2 位数 → 密度翻倍）**。
- **校验**：`(Start值 + Σ(位置 × 符号值)) mod 103`，位置从 1 起。
- 编 `"AB12"`（B 集）：`A`=33、`B`=34、`1`=17、`2`=18 → 序列
  `[StartB(104), 33,34,17,18, 校验, Stop]` → 查表展开成条/空宽度 → 画出来。

**关键**：Code128 是有限、全公开的编码（107 行表 + 一个 mod 103 校验），所以**内嵌表自己
实现即可，0 依赖**——跟农历 `lunar`、secrets 规则表一个路子。

## 用法

```bash
jdan barcode [data]
```

```bash
jdan barcode "ABC-123"             # 终端竖条 + 下方人眼可读文本
jdan barcode 5901234123457 -o label.png
jdan barcode "SKU42" -o tag.svg
echo "data" | jdan barcode         # stdin
jdan barcode "ABC-123" --json
```

### Flags

| flag | 默认 | 说明 |
|------|------|------|
| `[data]` | — | 要编码的字符串（位置参数或 stdin） |
| `--output` `-o` | 终端 | 写文件，按扩展名识别 `.png` / `.svg` |
| `--module` `-m` | PNG=2 / 其余=1 | 模块宽（PNG 像素 / SVG 单位 / 终端列数） |
| `--height` | 80 | 条高（PNG/SVG 像素；终端固定几行） |
| `--invert` | false | 反色 |
| `--no-text` | false | 不显示下方人眼可读文本 |
| `--json` | false | 元信息 `{data, code_set, checksum, modules}` |

## 字符集自动选择

| 输入 | 字符集 | 说明 |
|------|--------|------|
| 含字母/标点 | **B** | 可打印 ASCII 32–126；超出范围（中文、控制符）报错 |
| **全数字 + 偶数长度** | **C** | 一个符号编 2 位数，**宽度减半** |
| 全数字但奇数长度 | B | 回退（C 必须成对） |

例：`12345678`（8 位偶数）→ C 集，99 模块；`1234567`（7 位奇数）→ B 集，更宽。

## 输出

- **终端**：整列 `█` 竖条（几行高）+ 两侧静区 + 下方居中人眼文本。
- **PNG**：黑白条（`image/png`，stdlib）。**不画人眼文本**（要字体依赖，故略）。
- **SVG**：黑色 `<rect>` 条 + `<text>` 人眼文本（浏览器自带字体，免依赖）。

静区：两侧各留 10 模块（不留扫不出来）。

## 退出码

| 状况 | code |
|------|------|
| 成功 | 0 |
| 空输入 / 非 ASCII 字符 / 不支持的输出扩展名 | 非 0 |

## 实现

```
internal/barcode/code128.go   Encode(data) (Symbol, error) —— 纯函数：data → 模块位图
                              + 内嵌 107 行模式表 + mod103 校验 + B/C 字符集选择
internal/cli/barcode.go        jdan barcode：Encode → 渲染 终端 / PNG / SVG
```

- `Encode` 纯函数。测试**手算校验向量**钉死：`"A"`→校验 34、`"AB"`→102、`"00"`(C集)→2；
  并断言模式表完整性（0–105 每行 6 元素和=11，Stop 和=13）、静区、模块数。
- 渲染层注入 out 可测：PNG 用 `png.Decode` 验证是合法图、SVG 断言含 `<rect>`/`<text>`。

## 有意不做

| 不做 | 原因 |
|------|------|
| EAN-13 / UPC-A / Code39 / Code93 | 各有固定位数 / 独立校验位规则，是另一套；Code128 先覆盖通用场景 |
| 中途切换 code set 的最优压缩 | 复杂、收益小；B + 全数字 C 已覆盖常见情况 |
| 条码**识别**（图 → 数字） | 要图像处理 / 定位，比生成重得多（跟 `qr` 没做解码同理） |
| PNG 里的人眼文本 | 要内嵌字体依赖；终端和 SVG 已能显示 |

跟 `jdan qr`（二维码）互补：`qr` 编任意文本的 2D 码，`barcode` 编一维 Code128（物流标签场景）。
